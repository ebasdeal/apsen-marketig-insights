## 6. Lacunas / ambiguidades

1. **Dois universos de produto**: o catálogo real Apsen (`familias`/`skus`: ENIAGOR, LEVOXIN… com código entre parênteses) convive com moléculas ilustrativas (Baricitinibe `SKU-00312`, Apixabana…) usadas em `aprovacoes`, `skuMeta`, `planoItens`, `skusCiclo`, `moleculaSkus`, `analises`, `restricoes`, `ingeridos` e no modal de inclusão do plano. Famílias do plano/análise (Imunologia, Cardio…) são terapêuticas, não as famílias de marca. Definir a fonte de verdade.
2. **Drivers × Aprovações desconectados**: `drvAdd` grava em `drivers` mas nada entra na Fila de Aprovação; `aprovacoes` tem esquema diferente (`periodo.ini/fim`, `tipo` = label com emoji, `params` string) do `drivers` (`periodo.inicio/fim`, `tipo` = slug, `parametros` objeto).
3. IDs inconsistentes: `ingeridos` DRV-2026-028 é "Apremilaste Digital", mas em `aprovacoes` é Aripiprazol **rejeitado**; `APROV_INGERIDOS` inclui DRV-2026-028 (mostra "Em uso no Data Lake" num rejeitado); análises citam `DRF-2026-031/030` inexistentes; ciclos dizem "4/7/5 ingeridos" sem vínculo.
4. `drivers` originais usam `id: Date.now()+n` → substituídos por 1–4 no db.json. Os 4 drivers iniciais não incrementam `badge-lista` (fica 0).
5. Badge "Catálogo de Tipos" = 40 e texto "38 ativos" fixos; dados têm 47 tipos / 45 ativos.
6. **Bugs no salvar driver**: modo Franquia referencia `FRANQUIA_SKUS` inexistente (L6099 → ReferenceError); modo SKU lê `sku.molecula`/`sku.codigo` que não existem em `SKU_DB` (gravam vazio); modo Família busca `skus_afetados_ia` em `MOLECULA_SKUS` (nomes de molécula) → sempre `[]` para famílias reais.
7. `DYN_IDS` não contém os campos de `posicionamento`, `presc_digital` e `protocolo_clin` (17 ids) → esses parâmetros não são salvos. `d_tipo_fv` é usado por `fv` e `farmacovig` (colisão de chave `tipo_fv`); `d_canal/d_formato/...` repetem entre tipos de mídia (ok, só um tipo por vez).
8. `BADGE` mapeia para classes `b-*` que não existem no CSS (existem `db-*`) → badges de tipo na lista/catálogo saem sem cor. Mapa `CAT_BADGE` (L6208) não é usado e cita `db-midia` inexistente. Definir mapeamento tipo→cor.
9. `formAplicarModo` usa ids inexistentes (`form-titulo`, `form-sub`, `form-view-banner`, `form-hdr-actions`): títulos/banner/botões de view/edit nunca aparecem e o botão continua "Adicionar Registro". Em edição de tipo de categoria 0 (Mídia) `TIPO_CAT[tipo]` é 0 (falsy) → tipo não é recarregado (L7775).
10. Data Fim tem `*` mas não é validada como obrigatória; Data Início sem `*`. Título não é obrigatório. `drvReset` põe intensidade 3 sem atualizar legenda/uplift; o padrão do HTML e do pós-salvar é 1.
11. **Permissões contraditórias**: `perfis` (nível 3) só é alcançável pelo menu para Admin; `PERFIL_HINTS.viewer` e a matriz dizem que Visualizador vê drivers ingeridos/tipos, mas `SCREEN_ROLES` exige 3; banner da Área diz que planos são só do Planejador, mas `planos` é nível 1; Visualizador pode incluir/editar/excluir itens do plano (botões sem checagem; `btn-plano-incluir` não existe). Matriz não cobre análises, restrições, ciclos, agentes, fontes.
12. `toggleMod` só fecha `drivers/admin/acesso/ciclos/agentes` (lista desatualizada); Dashboard abre o accordion de Drivers; classes `.teal/.purple` de item ativo não são aplicadas.
13. Telas sem lógica/persistência: busca/filtros de `usuarios` e `ingeridos`; botão "Ver" de ingeridos; salvar de tipo-form, user-form, agente-form (inputs sem id), modal-ciclo (inclusive "Editar" abre o modal vazio), modal-importar; excluir tipo/usuário/ingerido só mostram toast. `modal-cat-drivers` é órfão.
14. Restrições: "Editar" abre o modal pré-preenchido mas salvar **cria** um novo registro (e não pré-preenche prazo/responsável); contadores das abas são estáticos; ícone de vazio compara `'ativa'` com `'ativas'`.
15. Rejeição grava só o motivo; a justificativa detalhada é descartada.
16. Análises: busca por ciclo compara caixa diferente (`'plp'` não casa); escolha de modelo guiado/avançado, horizonte e drivers desmarcados são ignorados (resultado fixo "Automático → SARIMAX", gráfico sempre 12 meses); drivers sugeridos não são filtrados pelos SKUs; `analiseSalvar` rebaixa "relatorio" para "salva".
17. Plano: id de novo item = `len+1` (colide após exclusões); checkbox "selecionar todos" sem ação em lote; ordenação por "Código" compara strings; itens aprovados só têm "Visualizar" mas a tela de detalhe permite editar e salvar.
18. Agentes: alerta "5 agentes · 3 ativos / próxima execução 03h00" é fixo; teste de conexão é aleatório (85% ok). Ambiente "Dev" nos dados × "Desenvolvimento" no select.
19. Dashboard: barras por categoria caem para número aleatório se a contagem for 0; timestamp "Atualizado em" é o relógio local.
20. Fontes: JSON paths e token não são gravados; o autocomplete de concorrentes nunca consulta `fontes` (sempre mock local).
21. Ciclo ativo "PLP-2026-07" está hardcoded em vários textos (planos, dashboard, alertas); não há regra de qual ciclo alimenta `planoItens`.
22. Role bar e link "Plano MVP" são artefatos do protótipo — confirmar se viram troca de perfil real (auth) ou ficam só em dev.
